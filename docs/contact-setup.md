# Приём заявок на info@taucloud.kz

Форма отправляет POST /api/contact. Письмо направляется только на info@taucloud.kz, поле email клиента удалено; для обратной связи используется указанный телефон. Подтверждение появляется после принятия письма SMTP-сервером; это не гарантия попадания во входящие (проверьте также спам). При ошибке значения остаются в форме. Повторный клик блокируется во время запроса и после успеха до изменения полей.

## Подключение Netlify

1. У почтового администратора получите SMTP_HOST, SMTP_PORT (587 STARTTLS или 465 TLS), SMTP_USER, SMTP_PASSWORD и разрешённый адрес отправителя SMTP_FROM.
2. В настройках Netlify добавьте эти переменные для Functions. Не добавляйте префикс VITE_: секреты не должны попадать в браузер.
3. Разверните проект с существующим netlify.toml. Обработчик netlify/functions/contact.mjs регистрирует /api/contact.
4. Отправьте тестовую заявку с настоящим контактным телефоном. Проверьте получение на info@taucloud.kz, все поля письма. Если письмо попало в спам, проверьте SPF/DKIM/DMARC у почтового администратора.

Без реквизитов endpoint возвращает 503, а форма показывает контакт для ручного обращения. Реальная доставка пока не проверена. Только загрузки dist на статический хостинг недостаточно: потребуется серверный обработчик. Для другого Node-хостинга можно использовать экспорт server/contact.mjs (Web Request → Response), добавив маршрутизацию и ограничение запросов на стороне хостинга.

## Локальная разработка

Скопируйте .env.example в .env.local и заполните значения. Запустите npm run dev: Vite подключает тот же серверный обработчик. После изменения переменных перезапустите сервер. npm run preview показывает только сборку, без API.

## Проверки

node --test scripts/test-contact.mjs
npm run build

Сервер проверяет размеры и типы полей, имя, БИН, телефон и допустимую услугу. Письмо текстовое; клиент не может изменить получателя. Скрытое поле отсеивает простые боты. В Netlify настроено 5 запросов в минуту на IP/домен (локально лимит не применяется). Успех SMTP тестируется подставным транспортом, без отправки реальных писем. Автоматических повторов при сетевом сбое нет: при потере ответа сервер мог уже отправить письмо.

Документация: https://nodemailer.com/smtp и https://docs.netlify.com/build/functions/api/.
