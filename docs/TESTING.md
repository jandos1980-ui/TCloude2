# Проверки проекта

Сверено 2026-09-23. Требуются зависимости из `npm ci`; браузерные скрипты используют установленный Google Chrome через Playwright `channel: 'chrome'`.

## Основные команды

```sh
npm test
npm run typecheck
npm run build
```

`npm test` проверяет серверную форму с подставным транспортом, данные площадок, локализацию и освобождение звука. TypeScript проверяет TSX-компоненты, не весь JavaScript. Сборка запускает упаковку кадров через `prebuild`.

Для интерфейса запустите `npm run dev` в отдельном терминале, затем:

```sh
npm run check:visual
node scripts/check-languages.mjs
node scripts/check-frame-stream.mjs
```

| Скрипт | Настройки | Результаты |
| --- | --- | --- |
| `scripts/check.mjs` | `BASE_URL`, `QA_OUTPUT` | По умолчанию `test-results/site-audit/` |
| `scripts/check-languages.mjs` | `BASE_URL` | `test-results/i18n/` |
| `scripts/check-frame-stream.mjs` | `TAU_TEST_URL` | Проверки и итог в терминале |

URL по умолчанию — `http://127.0.0.1:5173`. Пример для PowerShell:

```powershell
$env:BASE_URL = 'http://127.0.0.1:5173'
$env:QA_OUTPUT = 'test-results/manual-review'
npm run check:visual
Remove-Item Env:BASE_URL, Env:QA_OUTPUT
```

Для проверки готовых файлов выполните сборку и `npm run preview`; используйте адрес, показанный Vite. API в этом режиме отсутствует. Проверки с перехватом запросов подтверждают интерфейс, но не доставку SMTP.

## Что проверять после изменений

- Контент/площадки: тесты данных, сборка, правильные изображения, статусы, галереи и CTA.
- Интерфейс: 320, 390, 600, 601, 800, 1280, 1366 и 1920 px; отсутствие переполнения, клавиатура, видимый фокус, Escape и возврат фокуса из диалогов.
- История: движение вперёд и назад, быстрые переходы, пересечение границы 600 px, уменьшенное движение, резервная загрузка кадров.
- Локализация: все три языка, динамические тексты, сохранение выбора и введённых полей, неизменность значений услуг для API.
- Форма: обязательные поля, ошибка с сохранением ввода, блокировка повторного клика, успех и новая заявка. Используйте подставной транспорт или перехват API.
- Документация: соответствие исходникам, локальные ссылки, `git diff --check`; повторный запуск приложения не требуется.

Перед выпуском дополнительно выполните `npm audit` и оцените найденные проблемы; не применяйте автоматически `npm audit fix --force`.

## Отчётность

Указывайте дату, состояние исходников, команды, фактические результаты и непроверенные сценарии. Снимки храните в `test-results/`, итог — в датированном отчёте `docs/`. Последний общий аудит: [2026-09-23](site-audit-20260923.md). Его результаты нельзя приписывать последующим изменениям.

Автоматический Chrome-аудит не заменяет Safari/Firefox, физические устройства, проверку медленной сети, полную доступность и нагрузочное тестирование.
