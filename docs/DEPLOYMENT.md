# Публикация и откат

Состояние на 2026-09-23: конфигурация Netlify есть, публичный адрес и реальная доставка SMTP не подтверждены. Ниже — порядок будущего выпуска, а не отчёт об уже выполненной публикации.

## Подготовка

1. Выберите проверенное состояние исходников и зафиксируйте его коммит. Сохраните идентификатор предыдущего рабочего выпуска и его конфигурацию.
2. Используйте Node.js 20.19+ или 22.12+ согласно требованиям проекта; согласуйте конкретную версию локально и на хостинге.
3. Выполните `npm ci`, затем проверки из [TESTING.md](TESTING.md) и `npm run build`.
4. Убедитесь, что исходные кадры и манифесты доступны сборщику. `prebuild` создаёт потоки; их отсутствие в Git само по себе не ошибка.

## Netlify

Проект содержит `netlify.toml`: команда сборки `npm run build`, каталог публикации `dist`. Файл `netlify/functions/contact.mjs` экспортирует обработчик и объявляет маршрут `/api/contact`, а также ограничение 5 запросов за 60 секунд по IP/домену. Применение маршрута и лимита необходимо проверить на хостинге.

В окружении Functions задайте переменные из `.env.example`:

| Переменная | Назначение |
| --- | --- |
| `SMTP_HOST` | Сервер исходящей почты |
| `SMTP_PORT` | 587 с STARTTLS либо 465 с TLS |
| `SMTP_USER` | Учётная запись SMTP |
| `SMTP_PASSWORD` | Секрет учётной записи |
| `SMTP_FROM` | Разрешённый адрес отправителя |

Не используйте префикс `VITE_`, не включайте секреты в репозиторий, скриншоты и отчёты. Получатель фиксирован в серверном коде: `info@taucloud.kz`. Подробности — [contact-setup.md](contact-setup.md).

Конфигурация содержит fallback `/* → /index.html` и защитные заголовки. Проверяйте, что API возвращает JSON, а не HTML fallback. `X-Frame-Options: DENY` запрещает встраивание страниц: вспомогательный просмотр через iframe может не работать на опубликованном домене.

## Проверка выпуска

- Открыть главную с чистым кешем на мобильной и десктопной ширине; проверить загрузку изображений, видео и кадров без 404.
- Переключить RU/KZ/EN, перезагрузить страницу, проверить меню, галереи и переход к форме.
- Проверить, что запрос `GET /api/contact` возвращает 405: это безопасная проверка маршрута без отправки письма.
- Проверить клиентскую форму с перехваченным API. Реальную тестовую заявку отправлять только по отдельному поручению; после этого подтвердить получение письма, включая папку спама.
- Записать URL, коммит, дату, выполненные проверки и ограничения. Успешная сборка сама по себе не подтверждает рабочую почту.

## Откат

При регрессии восстановите предыдущий проверенный выпуск средствами хостинга либо пересоберите его коммит. Сверьте совместимость Functions и окружения: откат статических файлов не гарантирует откат настроек SMTP. Повторите проверки главной, медиа и API. Не исправляйте `dist/` вручную.

## Другой хостинг

Нужны статическая раздача `dist/` и серверный адаптер для `server/contact.mjs` с интерфейсом Web Request → Response. Готового самостоятельного Node HTTP-сервера в проекте нет. Маршрутизацию, окружение, лимит запросов и заголовки потребуется настроить отдельно.
