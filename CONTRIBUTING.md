# Разработка TAU CLOUD

Рабочий язык документации — русский. Начните с [README.md](README.md), [AGENTS.md](AGENTS.md) и [архитектуры](docs/ARCHITECTURE.md).

## Порядок изменений

1. Проверьте `git status --short`; сохраните существующие незакоммиченные изменения. Уточните критерий готовности задачи.
2. Для отдельной задачи используйте отдельную ветку; ветки Codex по умолчанию имеют префикс `codex/`. Автоматически коммитить или публиковать изменения не требуется.
3. Вносите изменения в исходники, не в `dist/` и `node_modules/`. Не смешивайте задачу с массовым форматированием или обновлением зависимостей. При изменении пакетов обновляйте и lock-файл.
4. Выполните относящиеся к задаче [проверки](docs/TESTING.md), изучите diff и выполните `git diff --check`.
5. В описании изменения укажите проблему, результат, выполненные проверки и ограничения. Обновите документацию, а значимое изменение — в [CHANGELOG.md](CHANGELOG.md).

## Критерии готовности

- Сохранены мобильная навигация, клавиатура, фокус, CTA и уменьшенное движение.
- Изменённые тексты проверены на RU/KZ/EN; API-значения услуг не зависят от языка.
- Данные площадок подтверждены предоставленными материалами; проектные объекты и визуализации обозначены корректно. Нет неподтверждённых заявлений о Tier III.
- Форма сохраняет данные при ошибке и не показывает ложный успех; тесты не отправляют реальные письма.
- Медиа, нужные сборке или восстановлению, сохранены по [ARCHIVE.md](docs/ARCHIVE.md).
- Результат и следующий шаг отражены в разделе 7 `AGENTS.md`. Непроведённые проверки не объявлены успешными.

Секреты храните только в локальном/серверном окружении. Публикация, настоящая отправка писем и платная генерация требуют соответствующего поручения. Фирменный логотип сохраняйте без произвольного перекрашивания.
