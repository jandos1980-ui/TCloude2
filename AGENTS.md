# AGENTS.md — TAU CLOUD

Инструкции для Codex и других ИИ-агентов. Область действия — весь репозиторий; вложенные `AGENTS.md`, если появятся, уточняют правила для своих каталогов. Явные инструкции пользователя имеют приоритет. Общение и рабочие заметки ведите на русском языке.

## 1. Назначение проекта

Сайт дата-центра TAU CLOUD на русском, казахском и английском языках: визуальная история, услуги, отрасли, надёжность, площадки и форма заявки. Сохраняйте адаптивность, доступность и корректную работу при уменьшенном движении (`prefers-reduced-motion`).

## 2. Стек и архитектура

- Node.js: по README требуется 20.19+ или 22.12+; пакетный менеджер — npm, зависимости закреплены в `package-lock.json`.
- Vite 7, ES Modules, основной интерфейс на JavaScript и CSS.
- React 19 и TypeScript для отдельных компонентов в `src/components/ui/`; это не полностью React-приложение.
- Framer Motion, Embla Carousel, Lenis, Lucide; Manrope подключён локально через `@fontsource-variable/manrope` в `src/main.js`.
- Сервер: `server/contact.mjs`, Nodemailer, POST `/api/contact`; адаптер Netlify Functions в `netlify/functions/contact.mjs`.
- Проверки: Node.js test runner, TypeScript, Playwright/Chrome. Обработка медиа: Sharp и FFmpeg; в зависимостях есть Krea SDK.

## 4. Команды разработки и проверки

Выполняйте команды из корня проекта.

| Команда | Назначение и условия |
| --- | --- |
| `npm ci` | Установить зависимости по lock-файлу |
| `npm run dev` | Локальный сервер, обычно `http://127.0.0.1:5173`, с API формы |
| `npm test` | Тесты серверного обработчика и данных площадок |
| `npm run typecheck` | Проверить TSX из `src/components/`; не проверяет весь JavaScript |
| `npm run build` | Собрать сайт в `dist/` |
| `npm run preview` | Просмотреть сборку; API заявки отсутствует |
| `npm run check:visual` | Браузерная проверка; нужен запущенный dev-сервер и установленный Chrome |

`predev` и `prebuild` запускают `scripts/pack-sequence.mjs`. Не удаляйте исходные кадры и манифесты, необходимые упаковщику. Для браузерной проверки доступны `BASE_URL` и `QA_OUTPUT`; подробности — в `docs/site-audit-20260921.md`.

После изменения поведения запускайте относящиеся к нему тесты и сборку; при изменении TSX — также typecheck, при изменении интерфейса — соответствующую браузерную проверку. Для правки только документации достаточно проверить содержимое и diff. Не называйте проверку успешной, если её не запускали; фиксируйте ошибки и ограничения.

## 5. Правила изменений

- Перед работой прочитайте этот файл, проверьте `git status --short` и изучите относящиеся к задаче исходники. Не затирайте чужие незакоммиченные изменения.
- Делайте изменения в пределах запроса. Сохраняйте существующий стиль кода; избегайте попутного массового форматирования, смены стека и обновления зависимостей.
- Не редактируйте `dist/` и `node_modules/` как исходники. При изменении зависимостей поддерживайте согласованность `package.json` и `package-lock.json`.
- Сохраняйте управление с клавиатуры, фокус, мобильную навигацию, работу CTA и режим уменьшенного движения. Изменения истории проверяйте при прокрутке в обе стороны и переходах между сценами.
- Сохраняйте фирменный логотип без произвольного перекрашивания. Не добавляйте неподтверждённые мощности, сроки, статусы площадок или заявление о сертификации Tier III; отличайте действующие объекты от проектных и визуализации от документальной съёмки.
- Не публикуйте сайт, не отправляйте реальные письма и не запускайте платную генерацию без соответствующего поручения пользователя. Обычные тесты формы используют подставной транспорт или перехват API.

## 6. Секреты, форма и медиа

- SMTP настраивается по `.env.example` и `docs/contact-setup.md`. Секреты держите в локальном окружении/на хостинге; не записывайте их в Git, браузерный код, отчёты и этот файл. Не используйте префикс `VITE_` для SMTP-секретов.
- Получатель заявки фиксирован: `info@taucloud.kz`. Сохраняйте серверную валидацию, защиту от повторной отправки, данные формы при ошибке и честное сообщение об отсутствии настроенного SMTP.
- Не журналируйте персональные данные заявок и почтовые реквизиты. Успех SMTP означает принятие письма сервером, а не подтверждённую доставку во входящие.
- Обычный статический `dist/` не заменяет серверный обработчик `/api/contact`.
- Не запускайте очистку автоматически. `npm run clean` удаляет `node_modules`, `dist`, `test-results`; `clean:all` дополнительно удаляет `.media-staging` и недопустим при незавершённом импорте/генерации.
- Берегите `public/media/ambient/`, исходные кадры и `manifest.json`. Отклонённые генерации, мастер-видео и QA-материалы переносите во внешнее хранилище только с манифестом архива; до выбора хранилища не удаляйте их. См. `docs/ARCHIVE.md`.
